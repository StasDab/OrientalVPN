# ТЗ: Telegram-бот для продажи VPN-подписок

## 1. Цель
Запустить Telegram-бота, который:
- продает VPN-подписки через Telegram Payments;
- автоматически выдает пользователю доступ (subscription URL/конфиг);
- продлевает/отключает доступ по сроку;
- поддерживает выбор локации сервера.

## 2. Бизнес-ограничения
- Пользователю выдается доступ на общий пул VPN-серверов, а не отдельный VPS.
- Локации для выдачи: минимум `Germany`, `Netherlands`, `Sweden`, опционально `Russia` при соблюдении локальных требований.
- Для каждой локации может быть несколько нод (пул).

## 3. Функциональные требования
### 3.1 Пользовательские сценарии
- `/start` — приветствие, правила, кнопки: `Купить`, `Пробный доступ`, `Мои подписки`, `Помощь`.
- `/buy` — выбор тарифа и локации.
- После выбора тарифа — создание `sendInvoice`.
- `pre_checkout_query` — подтверждение оплаты.
- `successful_payment` — создание/продление доступа.
- Отправка пользователю:
  - ссылки подписки;
  - короткой инструкции подключения (Happ/v2rayTun/другие).
- `/trial` — бесплатный доступ на ограниченный срок (например, 3 часа), один раз на пользователя.
- `/my` — текущий статус подписки, срок, локация, кнопка продления.

### 3.2 Админ-сценарии
- `/stats` — активные подписки, оплаты за период, успешность выдачи.
- `/broadcast` — рассылка с подтверждением.
- `/add_days <user_id> <days>` — продление вручную.
- `/revoke <user_id>` — отключение доступа.
- `/servers` — статус серверов по локациям (load, active users).

## 4. Нефункциональные требования
- Надежность: идемпотентная обработка платежа и выдачи.
- Безопасность: секреты в `.env`, админ allowlist, rate limit.
- Наблюдаемость: структурные логи, метрики, алерты.
- Масштабируемость: добавление новых серверов без изменения логики бота.

## 5. Архитектура
- `bot` (aiogram 3.x): обработка команд, UI, платежи.
- `billing`: запись и сверка платежей, статусы подписок.
- `vpn_provider`: абстракция API панели (`MarzbanAdapter`/`XuiAdapter`).
- `server_selector`: выбор локации и ноды по доступности/нагрузке.
- `scheduler`: фоновые задачи (истечения, напоминания, ретраи).
- `db`: PostgreSQL.
- `cache/queue`: Redis.

## 6. Модель данных (минимум)
- `users(id, tg_id, username, created_at, is_blocked)`
- `plans(id, code, title, price_kop, duration_days, is_trial)`
- `locations(id, code, title, is_enabled)`
- `vpn_nodes(id, location_id, provider, api_url, capacity, is_enabled, health_status)`
- `subscriptions(id, user_id, plan_id, node_id, external_user_id, subscription_url, starts_at, ends_at, status)`
- `payments(id, user_id, telegram_payment_charge_id, provider_payment_charge_id, amount_kop, currency, status, raw_payload, created_at)`
- `events(id, type, payload, status, retries, created_at, updated_at)`

## 7. Логика выдачи доступа
1. Получен `successful_payment`.
2. Проверка идемпотентности по `telegram_payment_charge_id`.
3. Выбор ноды по локации (least-loaded + health_status=ok).
4. Создание/продление пользователя в VPN-панели.
5. Запись в `subscriptions`.
6. Отправка subscription URL пользователю.
7. При ошибке — запись `events` и retry с backoff.

## 8. Фоновые задачи
- Каждые 10 минут:
  - искать истекшие подписки и отключать доступ в панели;
  - отправлять reminder за 24 часа до окончания;
  - повторять неуспешные события выдачи.

## 9. Интеграции
- Telegram Bot API / Telegram Payments.
- Платежный провайдер, поддерживаемый в BotFather для нужной юрисдикции.
- VPN-панель API (рекомендовано: Marzban).

## 10. Безопасность
- `.env` + секретное хранилище в проде.
- Подписи webhook (если используются) проверять.
- IP allowlist к VPN-панели.
- SSH только по ключам.
- Аудит критических админ-действий.

## 11. Критерии приемки MVP
- Пользователь может купить подписку в 2-3 клика.
- После оплаты доступ приходит <= 30 секунд.
- Просроченные подписки отключаются автоматически.
- Напоминание о продлении приходит заранее.
- Админ-команды работают только для allowlist.

## 12. Roadmap после MVP
- Реферальная программа.
- Промокоды и купоны.
- Автовыбор лучшей ноды по latency.
- ЛК на web-панели поверх API бота.
