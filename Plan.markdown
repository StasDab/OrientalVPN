# План запуска VPN-сервиса через Telegram-бота

## 1) Что строим
- Telegram-бот продает подписку, принимает оплату, автоматически выдает пользователю VPN-конфиг/ссылку.
- Управление доступом делается через VPN-панель (предпочтительно Marzban API; 3X-UI возможен, но часто менее предсказуем по API и обновлениям).
- Пользователь не получает root-доступ к VPS. Он получает только клиентский доступ (ключ/ссылку).

## 2) Бизнес-модель инфраструктуры (критично)
- Не выдавать отдельный VPS каждому клиенту по умолчанию: это дорого, сложно сопровождать и плохо масштабируется.
- Базовая модель: несколько общих серверов по регионам (например, NL/DE/TR), пользователи распределяются по пулам.
- Премиум-модель (опционально): отдельный VPS как дорогой тариф "личный сервер", где бот запускает отдельный инстанс автоматически.
- На старте достаточно 2-3 VPS и автоскейл "добавить сервер при загрузке >70% или росте latency/packet loss".

## 3) Минимальная архитектура
- `bot-service` (Python, aiogram 3.x): тарифы, платежи, личный кабинет, уведомления.
- `billing-service` (в том же приложении или отдельно): сверка платежей, продление, возвраты/споры.
- `vpn-control-service`: адаптер к API Marzban/3X-UI (create user, disable user, extend expiry).
- `db` (PostgreSQL): пользователи, подписки, платежи, серверы, выдачи конфигов, аудит.
- `queue` (Redis + Celery/RQ или APScheduler): фоновые задачи (истечения, ретраи, рассылки).
- `monitoring`: Prometheus + Grafana + централизованные логи (Loki/ELK).

## 4) Платежи в Telegram (важные уточнения)
- Использовать Telegram Payments (`sendInvoice`, `pre_checkout_query`, `successful_payment`) с официальным провайдером, доступным для вашей юрисдикции.
- Для РФ обычно рассматривают ЮKassa, но доступность конкретного провайдера в BotFather и условия могут меняться: это нужно проверить перед разработкой.
- Telegram и эквайер берут комиссии; закладывайте их в юнит-экономику (не считать комиссию нулевой).
- Рекомендуется хранить idempotency-ключи: повторный webhook/апдейт не должен выдавать доступ дважды.

## 5) Где арендовать VPS (практический список)
- Международные: Hetzner, OVHcloud, DigitalOcean, Vultr.
- С оплатой и поддержкой в РФ (в зависимости от текущих условий): Selectel, Timeweb Cloud, firstVDS, VK Cloud.
- Что проверять перед покупкой:
  - стабильный аптайм и репутация DC;
  - локации (нужны страны, удобные вашей аудитории);
  - политика провайдера по VPN-нагрузке и abuse-жалобам;
  - ограничение трафика и честная полоса;
  - возможность API для автоподнятия серверов;
  - способы оплаты и закрывающие документы.

## 6) Как "выдавать сервер после подписки"
- Рекомендуемый вариант: после оплаты выдавать не VPS, а персональный ключ на существующем сервере.
- Для тарифа "личный VPS":
  1. бот фиксирует успешную оплату;
  2. оркестратор создает VPS через API провайдера;
  3. cloud-init/Ansible ставит Docker + Marzban/Xray;
  4. создается пользователь и subscription URL;
  5. бот отправляет ссылку и статус развертывания.
- Добавить таймауты и ретраи: если провайдер/API недоступен, заказ не теряется, а уходит в очередь повторов.

## 7) Безопасность (обязательно)
- Секреты только в `.env`/Vault, не в коде и не в git.
- Доступ к серверам только по SSH-ключам, парольный вход отключить, включить fail2ban/UFW.
- Админ-команды бота доступны только allowlist Telegram ID.
- API-панель VPN закрыть по IP/ACL + отдельные креды на каждый сервис.
- Логи анонимизировать: не хранить лишние персональные данные и сырой трафик.

## 8) Юридическая и операционная часть
- Подготовить оферту, политику конфиденциальности, возвраты, правила использования.
- Проверить локальные требования к обработке платежей и хранению данных.
- Настроить саппорт-процессы: замена ключа, перенос устройства, возврат, антиабуз.
- Иметь план ротации IP и "горячую" замену серверов при блокировках/жалобах.

## 9) Рекомендованный стек для MVP
- Python 3.12, aiogram 3.x, PostgreSQL, Redis.
- Marzban API как основной backend управления доступом.
- Docker Compose для MVP, затем перенос в Kubernetes/nomad при росте.
- CI/CD: GitHub Actions + деплой через Ansible.

## 10) План внедрения по этапам
1. Подтвердить платежного провайдера в Telegram и пройти KYC/KYB.
2. Поднять 2 VPS в разных локациях + VPN-панель + мониторинг.
3. Собрать бота: тарифы, оплата, автовыдача, trial, продления, уведомления.
4. Внедрить метрики и алерты (оплата, ошибки выдачи, истечения).
5. Запустить закрытую бету на 20-50 пользователей.
6. Доработать антиабуз и поддержку, затем открыть публичный запуск.

## 11) Что изменить в исходной идее
- Оставить Telegram Payments + авто-выдачу: это правильно.
- Исправить тезис "Telegram ничего не удерживает": комиссии есть.
- Добавить слой оркестрации серверов и отказоустойчивые очереди.
- Сразу проектировать под PostgreSQL, а не SQLite, если цель — реальные продажи.
- В первую очередь выдавать ключи с общих серверов; отдельный VPS делать как премиум-опцию.
