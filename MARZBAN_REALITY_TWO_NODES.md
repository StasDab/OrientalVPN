# Отдельные ключи REALITY для двух узлов (EU + USA)

**«Максимальная гигиена»** здесь значит: у inbound **`loc-se`** и **`loc-us`** свои **`privateKey`** и при необходимости свои **`shortIds`**. Тогда компрометация или «связывание» одного узла не трогает второй.

## 1. Сгенерировать ключи на сервере, где есть Xray

Часто уже стоит из Marzban (`/usr/local/bin/xray`). Иначе временно в контейнере панели:

```bash
xray x25519
```

Вывод даст **новую** пару ключей (названия строк в выводе могут отличаться по версии Xray):

- **секретный** ключ вставь в `realitySettings.privateKey` только для **одного** inbound (например только `loc-us`);
- **публичный** (`pbk` в ссылке) Marzban покажет после сохранения конфига или в подписке.

**Новый shortId** (8 байт в hex, 16 символов):

```bash
openssl rand -hex 8
```

Подставь результат в `realitySettings.shortIds` у **того же** inbound (`["a1b2c3d4e5f60708"]`).

`dest` и `serverNames` (у тебя **`ads.x5.ru:443`** / **`ads.x5.ru`**) можно оставить **одинаковыми** на обоих узлах — это не про «гигиену» ключей, а про маскировку под сайт.

## 2. В Marzban Core JSON

- **`loc-se`** — оставить **текущие** `privateKey` + `shortIds` (как у работающего EU).
- **`loc-us`** — заменить **`privateKey`** и **`shortIds`** на сгенерированные на шаге 1 (не копировать от `loc-se`).

Сохранить → перезагрузить ядро.

## 3. Host в панели для каждого inbound

- **EU** — публичный IP/домен EU, порт **443**, **Fingerprint qq**, Primal SNI при необходимости = `ads.x5.ru`.
- **USA** — публичный IP USA (**77.110.127.4** и т.п.), порт **443**, те же правила.

После смены ключей у клиентов автоматически обновятся **`pbk`** и **`sid`** в подписке — пользователям нужно **обновить подписку** в клиенте (или импорт заново).

## 4. Бот

Менять код бота не нужно: в `VPN_NODES_JSON` по-прежнему два объекта с **`inbound_tag`: `loc-se`** и **`loc-us`**, один и тот же `api_url` панели — Marzban сам отдаст разные параметры в конфиг по тегу узла.
