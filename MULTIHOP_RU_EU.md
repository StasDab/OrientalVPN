# Multihop: клиент → VPS РФ (белый список / «проходимый» IP) → VPS EU (Marzban + Xray)

Цель: на LTE/ТСПУ в режиме **L3 whitelist** клиент подключается к **IP в РФ**, который оператор пускает; дальше трафик уходит на ваш **EU‑сервер**, где крутится Marzban и выход в интернет.

Важно:

- Смена только **SNI/dest** в REALITY **не заменяет** whitelist по IP: первый пакет всё равно идёт на **IP входа**.
- «Сто процентов» никто не гарантирует: политики операторов и списки меняются. Ниже — рабочая **инженерная** схема из практики и логики [статьи на Хабре](https://habr.com/ru/articles/1027276/) и ориентиров по «проходимым» ASN/IP ([репозиторий twl](https://github.com/openlibrecommunity/twl)).

## Про фразу «Trojan / Hysteria для обхода»

Это **про другие протоколы**, не про Marzban+VLESS+REALITY как у тебя сейчас.

- **Trojan** — трафик по сути «замаскирован» под обычный **HTTPS на TCP 443** (клиент шлёт TLS, внутри — свой туннель). Удобно там, где режут «не похоже на веб».
- **Hysteria** — чаще **UDP** (QUIC‑подобные режимы), на мобильных часто **быстрее и терпимее к потерям**. Но в жёстком режиме **белых списков** у части операторов **UDP почти убит** — тогда Hysteria может не взлететь, а **TCP 443** (Trojan / твой REALITY) остаётся разумнее.

Имеется в виду: «если не хочешь возиться с Xray REALITY — можно взять готовые стеки Trojan/Hysteria». У тебя уже Marzban на Xray — проще **добить multihop на VLESS**, чем параллельно поднимать второй стек.

## Одна ссылка подписки на всех (МТС и «чтобы везде»)

Физически **один TCP‑коннект не может одновременно идти на IP в РФ и на IP в Швеции**. «Работает везде» с **одной** строкой `vless://...` значит: в этой строке **один адрес сервера** — тот, который **всегда** доступен из любых сетей.

Практичный вариант под твой запрос:

- В подписке Marzban оставить **только один Host** — **российский IP** (вход на РФ‑релей). Прямой вход на EU **в подписку не добавлять**.
- Тогда у всех клиентов **одна** ссылка `/sub/...` и **один** узел в списке: все всегда ходят **РФ → EU** (чуть больше пинг с Wi‑Fi за границей, зато **одинаково** на МТС LTE и у большинства).

Если когда‑нибудь понадобится «снаружи РФ без лишнего прыжка» — это уже **вторая** точка входа (вторая строка или второй профиль), без этого «идеально короткий путь для всех стран и одна нога» не существует.

## Схема

```text
[Телефон LTE] --TCP443 REALITY--> [VPS РФ: Xray вход]
                                      |
                                      +--TCP (вторая нога)--> [VPS EU: Xray «внутренний» inbound]
                                                                 |
                                                                 +--> Marzban / интернет
```

- **Нога 1 (публичная, РФ):** VLESS + REALITY + Vision, порт **443**, адрес в подписке = **публичный IP РФ**.
- **Нога 2 (транзит РФ→EU):** отдельный inbound на EU (**не** REALITY для этой ноги), например **VLESS TCP без TLS** или **VLESS + TLS** с сертификатом, порт **высокий** (например `18443`), в **ufw только IP РФ**.

На EU технический inbound «только от РФ» остаётся; **в подписку для клиентов** при варианте «одна ссылка» вы не обязаны выкладывать прямой EU‑Host — все подключаются к РФ, дальше релей сам ведёт на EU.

## Шаг 0. Выбор IP РФ

Ориентиры из аналитики whitelist (см. [twl](https://github.com/openlibrecommunity/twl), [статью](https://habr.com/ru/articles/1027276/)): часто встречаются крупные хостинги/облака (Yandex Cloud, Selectel, VK, REG.RU, Timeweb и т.д.).  
Перед оплатой VPS проверьте с **той же SIM**, что у проблемных клиентов:

- открывается ли `https://<IP_РФ>:443` (хотя бы TCP, без обязательного HTTP);
- не режет ли оператор именно этот ASN.

## Шаг 1. EU (уже есть Marzban)

### 1.1 Второй inbound только для РФ‑релея

В Core (Xray) Marzban добавьте **отдельный** inbound, например:

- `tag`: `relay-from-ru`
- `protocol`: `vless`
- `listen`: `0.0.0.0`
- `port`: `18443` (пример; не 1337/8080 и т.п.)
- `settings.clients`: пустой список — пользователей добавляет Marzban как обычно, но **назначьте им этот inbound** только если хотите отдельный профиль релея (или один технический пользователь для теста).

Реальность (REALITY) на этой ноге **не нужна**: канал РФ→EU и так ограничен firewall по IP.

### 1.2 Firewall на EU

Разрешите вход на `18443/tcp` **только с IP РФ‑VPS**:

```bash
ufw allow from <IP_РФ> to any port 18443 proto comment 'relay from RU VPS'
ufw reload
```

Остальной мир на `18443` не должен попадать.

### 1.3 Скопировать REALITY‑ключи на РФ (для публичной ноги)

Marzban считает `pbk`/`sid`/`sni` из inbound на **EU**. В подписке при **одном Host (только РФ)** клиент всё равно получит эти же параметры, но подключаться будет к **IP РФ**.

Значит на **РФ** в Xray для входа REALITY нужно поставить **тот же** `privateKey`, `shortIds`, `serverNames`, `dest`, что и в `realitySettings` inbound на EU (ключ **дублируется** на двух машинах — осознанный компромисс для одной подписки и одного набора параметров). Если не хочешь шарить ключ — придётся отдельный inbound/ключи и отдельная ссылка (это уже не «одна подписка как сейчас»).

## Шаг 2. РФ (новый VPS, только Xray)

Установите Xray (тот же major, что в Marzban, по возможности).

### 2.1 Inbound: как у EU REALITY (порт 443)

Скопируйте блок `loc-se` (REALITY) с EU, поменяйте только `listen`/`port` при необходимости (443).

### 2.2 Outbound на EU «внутренний» inbound

Пример идеи (порт и UUID подставьте свои):

```json
{
  "tag": "to-eu-relay",
  "protocol": "vless",
  "settings": {
    "vnext": [
      {
        "address": "<IP_EU>",
        "port": 18443,
        "users": [
          {
            "id": "<UUID_КАК_В_MARZBAN>",
            "encryption": "none",
            "flow": "xtls-rprx-vision"
          }
        ]
      }
    ]
  },
  "streamSettings": {
    "network": "tcp",
    "security": "none"
  }
}
```

### 2.3 Routing

Правило: весь трафик с inbound клиента → `to-eu-relay`.

Проверка с РФ:

```bash
curl -fsSI https://www.gstatic.com/generate_204 -m 10
```

Если с РФ это OK, а с EU тоже OK — транзитный выход настроен.

## Шаг 3. Marzban: Host в подписке

**Вариант «одна ссылка для всех» (рекомендуется под МТС и «большинство»):** в Marzban для REALITY‑inbound заведите **один Host** — только **публичный IP РФ** (релей). Прямой Host с EU IP **не добавляйте** — в подписке будет **одна** строка `vless://...`.

**Вариант «два входа в одной подписке»:** два Host (EU + RU) — пользователь сам выбирает узел; тебе этот вариант не нужен.

## Шаг 4. Бот (этот репозиторий)

`VPN_NODES_JSON` по-прежнему указывает **`api_url`** на **EU** Marzban (создание пользователя, expire, revoke).  
Менять обязательно только если вы вынесли API на другой URL.

Пользователям можно в `/help` кратко написать: *«на LTE выберите сервер с российским IP из подписки»*.

## Шаг 5. Безопасность

- Ключ REALITY на двух серверах — компромисс: компрометация РФ = компрометация параметров ноги 1. РФ‑VPS держите максимально минимальным (только Xray, ssh по ключу, ufw).
- Реле‑порт на EU **не светите** в интернет без ограничения по IP РФ.
- Рассмотрите **отдельный UUID** только для релея и не смешивайте с публичной выдачей, если хотите изоляцию (тогда чуть сложнее синхронизация с Marzban).

## Если не хочется дублировать REALITY‑ключ

Альтернатива: **разные** inbound/tag и **разные** ссылки в подписке (EU REALITY / RU REALITY с разными `pbk`). Marzban тогда ведёт два набора Host/inbound — больше ручной работы, зато ключи не шарятся между серверами.

## Связь с рекомендациями из статьи

- **Multihop** `client → RF → EU` как раз снимает проблему «до EU IP пакеты не выходят из LTE».
- **Порты:** публично — **443/tcp**; внутренняя нога — нестандартный tcp + **ufw from RF only**.
- **UDP** в жёстком БС часто мёртв — опирайтесь на **TCP 443** на первой ноге.
- Репозиторий [twl](https://github.com/openlibrecommunity/twl) — ориентир по **L3**, не замена здравого смысла и теста с нужной SIM.

После развёртывания проверьте цепочку так: **LTE → подключение к RU‑адресу → сайт/204‑чек**. Если EU‑ссылка на том же телефоне не работает, а RU — работает, схема достигла цели.
